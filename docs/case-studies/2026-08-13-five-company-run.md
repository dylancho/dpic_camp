에이전트를 실제 기업 5곳에 돌린 기록. 전체 사이클(md 지시서 → 조사 → `evidence.json` → 채점)을
그대로 거쳤고, 증거 파일은 레포 루트에 함께 있다.

**주의: 아래 점수는 공개 자료만으로 나온 값이다.** 실사 자료가 들어오면 달라진다.
특히 B블록(해자)은 공개 조사로는 구조적으로 채워지지 않는다 — 아래 §3 참조.

## 2. 순서가 상업화 성숙도와 맞아떨어진다

하우스 철학은 **"Scalable, not experimental — 실험이 아니라 기술 검증을 마치고 대규모
상업화를 앞둔 기업"** 이다. 점수 순서가 그 축을 그대로 따라간다.

- **Phoenix Tailings** — 이미 200 t/yr 상업 생산 중(NdPr·Dy·Tb 3종), 1,000+ t/yr 확대 계획,
  Series B 누적 $116.6M + 국방부 $500M 조건부 확약
- **에스그래핀** — Nature 논문과 서울대 교수 대표라는 연구 역량은 확실하나, 시설이
  아직 **시험검증용 파일럿**이고 인증도 벤처인증·중소기업 확인 같은 **행정 인증**뿐

에스그래핀의 0점은 "기술이 없다"가 아니라 **"아직 실험 단계다"** 라는 판정이다.
원칙 (d)가 판별하려던 것이 정확히 이것이다.

**커버리지가 높다고 점수가 높지 않다.** 에스그래핀은 커버리지 40%로 가장 높은데
점수는 0점이다 — 조사가 부족해서가 아니라 조사 결과 `NOT_MET`이 3개(A2·C1·C2)이기 때문이다.

## 3. 5곳 전부 B게이트(해자)에서 막혔다

예외가 없다. B블록 4개 항목 — 거래소 기술성 평가 등급, 등록 특허 3건 이상, 석사 이상
인력 비중 60%, 랩·논문 이력 — 중 **공개 자료로 2개를 채운 회사가 하나도 없었다.**
에스그래핀만 B4 하나를 얻었고, 그것도 대표가 서울대 교수라는 특수한 경우다.

원인은 도구가 아니라 항목의 성격이다. 특허 등록 건수와 인력 학위 구성은 원래 **실사 자료**다.
비상장은 사업보고서를 내지 않으므로 DART에도 그 표가 없다(§5).

**팀 논의 제안**: B블록을 공개 조사 단계에서 평가하지 않고, 1차 스크리닝은 A·C(17점)로
하고 B는 실사 진입 후 채우는 2단계 운영이 실제 워크플로에 맞을 수 있다. 원칙을 바꾸자는
것이 아니라 **언제 채점하느냐**의 문제다.

## 4. 같은 정보인데 공시 여부로 점수가 갈린다

에이치투와 제이알에너지솔루션의 C블록 차이가 이를 보여준다.

| | 에이치투 | 제이알에너지솔루션 |
|---|---|---|
| C1 | 1공장 330MWh 준공(2023.05), 2공장 3배 이상 — **완공 시점 없음** → `NOT_MET` | 1공장 1.5GWh(2026.03), 2공장 2GWh(2027), 총 5.5GWh → `MET` |
| C2 | 투자 6건·Series C·한화 30억×2 — **총액 비공개, 용도 연결 없음** → `NOT_MET` | 시리즈A 617억 + 시리즈B 300억, **"시리즈B는 1공장 증설 자금"** → `MET` |
| C 점수 | 0/5 | 4/5 |

에이치투가 같은 정보를 공개하면 C블록이 바로 채워진다. **기술의 문제가 아니라 공시의 문제다.**
실사에서 물어볼 항목이 정확히 특정된다는 점에서 이 결과는 유용하다.

## 5. DART가 비상장에 대해 할 수 있는 일과 없는 일

5곳 중 DART에 정기공시가 있는 곳은 **없었다**.

| 기업 | DART 상태 |
|---|---|
| 범한메카텍 | 감사보고서 10건, 정기공시 0건 |
| 제이알에너지솔루션 | 감사보고서 2건, 정기공시 0건 |
| 에이치투 | 감사보고서 4건, 정기공시 0건 |
| 에스그래핀 | 공시 자체 없음 |
| Phoenix Tailings | 미국 법인 — DART 대상 아님 |

특허 보유현황과 연구개발 인력 구성 표는 **사업보고서에만 있다.** 비상장이 감사보고서만
제출하면 그 표는 존재하지 않으므로, B2·B3는 DART로 영원히 확인되지 않는다.
에이전트가 이 사실을 `research_notes`에 명시하고 md 지시서 경로로 안내한다.

**규칙 추출기는 애매하면 읽기를 거부한다.** 에이치투 감사보고서 4건 모두에서 특허 관련
섹션을 찾았으나 표 구조를 확신할 수 없어 판독하지 않았다(루닛에서도 같은 동작).
규칙이 만드는 증거는 전부 1급이라 오독을 등급 필터가 걸러주지 못하기 때문이다.

**감사보고서는 다른 축에 쓸모가 있다.** 범한메카텍 감사보고서 주석에서 계약부채 신호가
잡혔고, 이는 Economic Value 축(원칙 b)의 "수주잔고·계약부채 추이" 항목에 해당한다.
에이전트가 이를 감지해 해당 축 담당자에게 넘기라고 기록한다.

## 6. 해외 기업에 대한 미해결 문제

Phoenix Tailings에서 드러났다.

- `B1_exchange_tech_grade`는 **한국거래소** 기술성 평가다. 미국 법인에는 구조적으로
  해당이 없어 실사해도 영원히 채워지지 않는다
- DART·KIPRIS 모두 한국 시스템이라 경로 자체가 없다

원칙의 아키타입 예시에 Phoenix Tailings·CTR·Enevate가 들어 있으므로 하우스는 해외
기업을 검토 대상으로 본다. **B1에 해외 대체 기준이 필요하다** — 예: DOE·DoD 등
국책기관의 기술실사 통과, 또는 동등한 제3자 기술평가.

## 7. 등급 구성 — 점수가 무엇에 기대고 있는가

5곳 전부 **1~2급 근거가 0건**이다. 모든 MET이 언론 보도(3급) 또는 회사 자체 발표(4급)에
얹혀 있다. 에이전트가 이를 결과에 표시한다:

```
근거 구성: MET 3건 중 0건은 1~2급, 3건은 3~4급(언론·회사 자체 발표)
! MET 3건이 3~4급 근거에만 의존한다: A1_poc_reproducibility, C1_capacity_plan, C2_capex_funding.
  1~2급 근거로 보강되기 전까지는 실사에서 재확인할 것.
```

당초 설계는 3~4급 단독 `MET`을 자동 강등했으나, 그 정책에서는 5곳이 전부 0점으로
서로 구분되지 않았다. 정책을 완화하는 대신 **무엇에 기대고 있는지를 결과에 노출**하는
방식으로 바꿨다(§ `_CREDIBLE_TIERS`, 상수 하나로 원복 가능).

```bash
python -m agents.proven_scalability --company "범한메카텍"           --archetype industrial_hardware --evidence evidence-범한메카텍.json
python -m agents.proven_scalability --company "제이알에너지솔루션"   --archetype energy_infra        --evidence evidence-제이알에너지솔루션.json
python -m agents.proven_scalability --company "에이치투"             --archetype energy_infra        --evidence evidence-에이치투.json
python -m agents.proven_scalability --company "에스그래핀"           --archetype materials           --evidence evidence-에스그래핀.json
python -m agents.proven_scalability --company "Phoenix Tailings"    --archetype materials           --evidence evidence-phoenix-tailings.json
```

증거 파일은 `docs/agent-instructions/`의 md를 LLM 세션에 붙여넣고 조사해 만든 것이다.
DART 부분은 매 실행마다 자동으로 다시 조회된다.

## 9. 찾지 못한 회사

**아쿠아포터스**, **키토스** — 두 곳 모두 조사를 진행하지 못했다.

DART 법인 등록부 110,830건 전수 조회에서 해당 상호가 없었고(비상장 포함 전체 목록이다),
웹 검색에서도 회사로 식별되는 결과가 없었다. 비슷한 이름을 임의로 고르면 **엉뚱한 법인의
근거로 점수를 매기게 되므로** 증거 파일을 만들지 않았다.

정식 법인명·영문 상호·홈페이지 중 하나가 확인되면 바로 진행할 수 있다.
